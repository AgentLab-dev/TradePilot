```sql
-- every run stamps:
```

**Not the cause:**  
- Incremental `NOT EXISTS` blocking new days (would only block if that date already existed **in that same table**)

### What it means
Your org/repo has a rule like: **“Require signed commits”** / **“Commits must have verified signatures.”**

Each commit must be signed with:
- **GPG**, or  
- **SSH signing key**, or  
- **GitHub’s web UI “Verified” signing** (when you commit via the website)

GitHub then shows the commit as **Verified**. If it’s **Unverified** (or unsigned), merge is blocked.

### Why it happens
Common cases:
- Local `git commit` without signing configured
- Commits made by an agent/tool without a signing key
- Wrong/expired GPG key, or email on the commit doesn’t match the key
- Rebase/cherry-pick that dropped signatures

### How to fix
**1. Check which commits are unverified** on the PR’s Commits tab (look for “Unverified”).

**2. Enable signing locally** (SSH is usually simplest):

```bash
# Generate / use an SSH key, add it in GitHub → Settings → SSH and GPG keys → Signing keys
git config --global gpg.format ssh
git config --global user.signingkey ~/.ssh/id_ed25519.pub
git config --global commit.gpgsign true
```

**3. Re-sign the branch commits** (only if you own the branch and force-push is allowed):

```bash
git rebase --exec 'git commit --amend --no-edit -S' <base-branch>
# or for recent commits:
git rebase -i HEAD~N   # mark commits as "reword"/"edit" and re-commit with -S
git push --force-with-lease
```

Or soft-reset and make one new signed commit:

```bash
git reset --soft origin/main   # or your base
git commit -S -m "Your message"
git push --force-with-lease
```

**4. Confirm** each commit on the PR shows **Verified**, then merge should unlock.
