# pr-author

Package the change as a reviewable PR. Nothing is pushed until a human approves in the Tasks inbox.

## Steps
1. Read `payload.implementation` (branch, diff) and `payload.test_report` (verdicts, evidence).
2. Draft a PR **title** (identifier-first, e.g. `EDAEM-3772: <change>`) and **body**: summary, models touched, validation matrix table, dbt test evidence, reviewer checklist. No agent self-signature.
3. Emit the title/body/reviewers as `payload.pending_pr` and return `status = needs_input` with `pause_reason = "push branch + open PR for <ticket>"`.
4. **Only on approval**: `fqc-github.push_branch(branch)` then `fqc-github.create_pr(title, body, base=default_branch, reviewers)`.

## Output — `payload.pr`
`pending_pr{title,body,reviewers}, pushed (bool), pr_number, pr_url`.
`status = needs_input` until approved; `ok` once opened; `fail` if push/PR errors.

## Hard rules
- Never push or open a PR without approval — both `fqc-github` writes are gated (destructiveHint).
- Base branch = default/feature only; never target `qa` or `prod`.
- Body leads with the ticket key and the substance (what changed + evidence); no "generated by" footer.
- Monitor and resolve any Copilot review threads before merge (per repo policy).
